## 1. topic 738158 (8/30) — Pure RL, 레이팅 1132 ★ 초안 반박 사안

- **순수 멀티에이전트 self-play PPO**. 3단 커리큘럼: 멀티덱 모델 → 아키타입별 → 덱별.
- Entity Transformer **~12M 파라미터**. **C++ 벡터화 환경, RTX 3090에서 ~30 games/s.**
- 덱: Slowking, Ogerpon+Meganium. **최고 제출 1132 (8/30 05:00 UTC), 최종 1100~1160 예상.**
- 전체 공개는 Strategy 종료 후 예정.

**초안 1 §7의 "공개 RL 시도는 전부 룰베이스 이하" 문장은 이제 거짓이다.** 8/08 시점 증거로는 참이었으나
8/30 공개물이 1132(골드 컷 1139.5 인접)를 찍었다. 그대로 두면 채점 질문 ②(기술적 타당성)에서 치명적이다.

**교체 서술(정직하면서 더 강함)**: RL은 이 환경에서 **작동한다 — 단, 환경 처리량을 먼저 사는 팀에게만.**
그들은 C++ 벡터화 시뮬레이터(30 games/s)를 지었고 우리는 공식 엔진의 파이썬 경로만 썼다.
구속 조건은 알고리즘 선택이 아니라 **시뮬레이션 스루풋**이었다. 우리가 RL을 배제한 결정은 우리 예산에서는
옳았고, 그 판단 근거를 밝히는 것이 "우리 실패"를 "정량화된 자원 경계"로 바꾼다.

## 2. topic 737125 (8/23) — 동일 tarball n=7, sd 51.4 ★ §4 선행 공개물

- **바이트 동일 tarball 7회 제출: 855.6 / 779.2 / 777.9 / 764.2 / 760.8 / 729.9 / 687.4.
  mean 765.0, sd 51.4, range 168.2.** 가족 전체 14추첨 mean 776.9, sd 44.8 → 브론즈 838 통과는 14분의 1.
- 수렴 전 요동 실측: 동시 제출 동일 덱 2개가 689 vs 489 → 6경기 후 1011 vs 642. "수렴 전 레이팅은 거의 순수 노이즈."
- 로컬 프로토콜: **매치업당 400경기, CI가 분리될 때만 출고.** 40경기는 CI ±15pp로 모든 실효과보다 넓다.
  이 규율로 "명백히 옳아 보이는" 변경 3건 기각.
- 시그니처 명제: **"The pilot fixes decisions. Only the deck fixes arithmetic."** HP 브레이크포인트
  (+20 에너지 / +30 스타디움)만으로 652 → 853.8. 최종 ~500위/6,755, ML 없음, 룰 ~500줄.

**함의 (세 갈래, 전부 초안 수정)**

1. **§4의 "빌드=분포"는 더 이상 우리만의 공개 발견이 아니다.** 8/23에 공개됐고 우리는 9/13에 낸다.
   인용하지 않으면 심사자가 먼저 발견할 위험이 있다. **인용하고, 우리 기여를 재정의하라**:
   - 규모: 우리 57제출/17빌드 vs 그쪽 사실상 1가족 21추첨.
   - 우리는 분포를 **기각 규칙**으로 썼다 (S2~S4 자기 변경 3건을 이 기준으로 죽였다).
   - 우리는 **메커니즘 3개를 분리 측정**했다(sticky placement, 신규 제출 스케줄링 우선, 드리프트 통제 재제출).
     그쪽은 산포만 보고했다.
   - 우리는 **수렴이 분포를 붕괴시키는 것까지 관측**했다(1000경기 후 격차 8.3 vs ~50경기 산포 134).
   → 주장을 "우리가 분산을 발견했다"에서 "**분산의 메커니즘을 분해하고 그것을 출고 규칙으로 운영했으며,
     수렴으로 닫았다**"로 이동. 이게 사실이고 더 방어적이다.
2. **§2 덱 유지 결정에 대한 가장 날카로운 반증이다.** 그는 덱 산술(HP 브레이크포인트)만으로 +200을 얻었다.
   우리 §2는 "정책이 카드 ID에 묶여 게이트 재획득 예산이 없었다"고 쓰는데, **반대 사례를 먼저 인용하고
   반사실 비용을 명시**해야 한다. 숨기면 ⑥⑦ 채점에서 약점으로 읽힌다.
3. 그의 결론 6번은 "RL은 여기서 이기지 못했다 + 제출 환경에 torch가 없다"인데, **1번 항목(1132)과 충돌**한다.
   해소: RL팀은 추론 가중치를 torch 없이(numpy 순전파) 실어야 했을 것. 즉 "torch 부재"는 RL 무효의 근거가
   아니라 배포 제약이다. 우리는 이 구분을 정확히 써서 두 공개물을 동시에 인용할 수 있다 — 지형 판독력의 증거.

## 3. topic 737435 (8/25, v25) — 최종 평가 몬테카를로 ★ §4 상보 자료

- Meta Kaggle 전 에피소드(8/25 기준, LB 1000+ 제출 169개·108팀·~25k 게임)에 **Bradley-Terry 적합**,
  10경기 이상 페어는 실측 head-to-head로 대체(가위바위보 구조 때문), **14일 × 96경기/일 TrueSkill 업데이트를 500회 시뮬**.
- 미공개 파라미터(초기 sigma 200, beta 100, tau 2, 매치메이킹 폭)는 추정. 순위 스프레드를 지배하는 건
  **매치메이킹 타이트함과 승률 행렬**이라고 명시.
- 결과: 골드존 상위권도 5~95% 순위 구간이 넓다(예: LiamK 평균 12.0, 구간 7~19).

**함의**: §4에서 **상보 관계로 인용**하라 — 그들은 위에서 아래로(BT 모델 → 시뮬레이션),
우리는 아래에서 위로(동일 코드 반복 제출 → 실측 분포). 두 접근이 같은 결론에 도달했다는 문장은
"래더는 잡음 추정기"라는 우리 전제를 참가자 커뮤니티 합의로 격상시킨다.
또한 **Meta Kaggle 에피소드 전량**이라는 데이터 소스는 우리가 안 썼다 — 그림 B 보강에 검토 가치.

## 4. topic 737107 (8/23~24) — 마감 후 메타 리포트 ★ §5 검증·방법론 우위

- 8/18~22 공식 데일리 **23,313 게임** 파싱. "Kaggle은 각 날짜 최고점 에피소드만 공개하므로 **래더 상단만** 기술한다"를 명시.
- **덱 명명 오류 공개 정정**: 자동 라벨은 각 덱의 최고 레어도 ex를 이름으로 삼아 **1장짜리 테크 카드가 엔진을
  덮어쓴다**. Fezandipiti ex가 20대 덱 중 8개에 1-of로 들어가며, 덤프가 "Fezandipiti ex"라 부른 덱은 실제로 Alakazam 덱.
- 그 Alakazam 덱: 필드의 **11.4%(4위 규모), 49.6% skill-matched, 하위 60%에 18.3% vs 상위 10분위에 6.9%** — 저구간 편중.

**함의 두 개**

1. **우리 방법론이 이 오류에 면역이다.** `scripts/archetype_shares.py`는 최고 레어도 ex가 아니라
   **진화 라인 집합**(Alakazam = {741,742,743}, Dragapult = {119,120,121})으로 분류한다.
   → §5에 한 문장 추가 가치: "공개 덤프의 자동 라벨은 1-of 테크 카드로 덱을 명명해 20대 덱 중 8개를 오분류한다.
   우리는 진화 라인으로 분류했다." 채점 질문 ②(기술적 타당성)에 직접 꽂히는 저비용 문장이다.
2. **밴드 한정 서술 의무**: 데일리 덤프는 상단 표본이다. 737125도 "승률은 레이팅 밴드의 함수"를 강조했다
   (900+ 밴드에서 Grimmsnarl 43~61%). 우리 §5의 셰어에 **"상위 풀 기준"**을 명시하지 않으면 공격받는다.
   현재 초안은 "top pool"이라 쓰고 있으나 한 번 더 못 박을 것. 그리고 우리 덱이 저구간 편중이라는 외부 실측은
   §2 군중픽 역설의 **독립 확증**으로 인용 가능(11.4% 규모, 상위 10분위 6.9%).
